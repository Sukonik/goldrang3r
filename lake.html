Cluster · Summary — Tech Security

Stolen tokens, signed in

  • Cybernoz: Attackers signed into Microsoft 365 accounts at 79 organizations using stolen login tokens, racking up at least 497 successful sign-ins between July 14 and September 22 — no password guessing required, because the token itself is the key. SecureResearch: The same brief reports a Gheist campaign planting workflows through stolen GitHub tokens to print repository secrets into logs. Two different platforms, one lesson: when a token leaks, the attacker does not break in — they log in, and every session-revocation and token-lifetime control you skipped is the gap they walk through.

Cluster · Summary — Fintech Security

Keystone's drastic fix: destroy 18,835 wallets

  • CoinDesk: Keystone will destroy 18,835 unsold hardware wallets after a website breach exposed the key its devices use to prove they are genuine — a key that could let counterfeits pass the authenticity check owners rely on. The Hacker News: The same breach exposed 25,964 buyer records, some kept past the company's 180-day deletion promise after an automated cleanup tool failed silently. Recovery phrases and private keys were not exposed, and devices delivered before October 20 that pass authentication are considered genuine — but the episode shows how a website flaw can poison trust in hardware itself.

Cluster · Summary — Fintech Security

Bloom's 94-second drain

  • W3Rooster: An attacker drained about 9,408 SOL from 48 wallets tied to Telegram trading bot Bloom in roughly 94 seconds, using the wallets' own keys — how those keys were obtained remains unconfirmed. CT.com: Bloom puts the loss at $953,000 across nine traders, blames a remote code execution flaw in a third-party module, says no private keys were accessed, and pledges full reimbursement. The sting in the tail: five drained wallets had been inactive on the bot since early 2025 — keys handed to a trading bot keep working long after the trader stops paying attention.

Cluster · Summary — Fintech Security

Binance blocks the interview trap

  • Hokanews: Binance says it blocked multiple North Korea-linked attacks over the past week with no system damage and no asset losses — and used the announcement to warn about the “Contagious Interview” campaign, where fake job interviews, coding tests and software-install requests dress malware delivery up as recruitment. No breach to report is itself the story here: the defense worked, and the warning turns a blocked attack into a public service for everyone else's hiring pipeline. Treat any interview that asks you to run code from a stranger as a security event, not a job opportunity.

Cluster · Summary — Fintech Security

The Electrum trap, in full

  • CoinDesk: Yesterday's summary flagged the Electrum fee-bump theft; today's reporting fills in the mechanism, and it is nastier than it first looked. CoinDesk: A rogue server could swap a user's outgoing payment for its own transaction, then sit back while the wallet displayed the fake payment as merely pending — and when the user bumped the fee to unstick it, they signed the thief's payment for real. PYMNTS: The fix adds signature checks on unconfirmed transactions, but older versions stay exposed against malicious servers — so the advice is blunt: update, and check every address and amount before you sign, fee bump included.

Cluster · Summary — Fintech Security

CoinDCX owns the $16M

  • CoinDesk: The CoinDCX story ends its first chapter with an admission: the exchange now says the flagged $16M traces to deprecated wallets from its July 2025 hack, where users kept depositing even after the addresses were retired — and the sweep job meant to move those funds onward failed. The exchange says it credited affected users and absorbed the loss, while conceding it could have disclosed the incident faster. After a week of denial versus on-chain evidence, the takeaway for users is simpler than the argument: retired addresses should stop receiving money, and when they do not, someone has to own the gap.
